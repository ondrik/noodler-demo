Z3-Noodler · string constraint solving

Finding bugs in string-handling code
with an SMT solver

Sanitizers, URL checks and escaping functions are short, and they still have bugs. Each one rewrites a string and then checks it. We translate the code to string constraints and ask Z3-Noodler if an attacker's input exists. A sat answer comes with a concrete exploit. An unsat answer is a proof that no input works.

≤ 3.09 sper query

How it works

  1. Model the code. Every string operation has a counterpart in the SMT-LIB theory of strings: replace → str.replace_all, startswith → str.prefixof, a regex test → str.in_re. Z3-Noodler also accepts ECMAScript regexes as they are (re.from_ecma2020) and has str.to_lower.
  2. State the attack. Add the attacker's goal: the cleaned path contains ../, the browser sees //host, the SQL literal is not closed properly.
  3. Ask the solver. sat: the model is an input that triggers the bug. unsat: no input does, for strings of any length.

The results below come from a native build of the solver. Run in the playground opens a query in the Z3-Noodler playground, which runs the solver locally via WebAssembly, so you can change the code and try your own fix.

Real vulnerabilities

CVE-2024-22195 · CVE-2024-34064

Jinja2: HTML attribute injection through xmlattr

Jinja2's xmlattr filter turns a dictionary into HTML attributes: <div{{ {key: value}|xmlattr }}>. Values are HTML-escaped, but if an application passes a user-chosen key, the key itself can close the attribute name and start a new one, such as an event handler. This was reported as CVE-2024-22195. The fix in 3.1.3 turned out to be incomplete: CVE-2024-34064. The encoding below follows the real code: markupsafe.escape as five chained replace_alls and the validation regexes copied from each release.

1

Jinja2 3.1.2: no check on keys

python · jinja2/filters.py
rv = " ".join(
    f'{escape(key)}="{escape(value)}"'
    for key, value in d.items()
    if value is not None and not isinstance(value, Undefined)
)
Z3-Noodler · 0.03 s
sat · bug found
key = "\u{9}onmouseover"

A tab or a space in the key starts a new attribute: Jinja2 3.1.2 renders <div, a tab, and onmouseover="…">. We ran the key the solver found through the real Jinja2 3.1.2 release, and it produced the injected attribute.

SMT-LIB encoding cases/jinja-3.1.2.smt2 
; Jinja2 3.1.2, filter xmlattr (CVE-2024-22195):
;
;   <div{{ {key: value}|xmlattr }}>   renders   <div key="value">
;
;   rv = " ".join(f'{escape(key)}="{escape(value)}"' for key, value in d.items() ...)
;
; The key comes from the user.
(set-logic QF_SLIA)
(declare-const key String)
(define-fun escape ((s String)) String   ; markupsafe.escape
  (str.replace_all (str.replace_all (str.replace_all (str.replace_all (str.replace_all s
    "&" "&amp;") ">" "&gt;") "<" "&lt;") "\u{27}" "&#39;") "\u{22}" "&#34;"))
; In HTML, an attribute name ends at a tab, LF, FF, space, "/", "=" or ">".
; Can the key smuggle in a second attribute, an event handler?
(assert (str.in_re (escape key)
  (re.++ re.all (re.union (str.to_re "\u{9}") (str.to_re "\u{a}") (str.to_re "\u{c}")
                          (str.to_re " ") (str.to_re "/"))
         (str.to_re "onmouseover"))))

CVE-2023-24329

CPython: blocklist bypass in urllib.parse.urlsplit

Applications often reject dangerous links by checking urlsplit(url).scheme. Browsers follow the WHATWG URL standard, which first strips leading control characters and spaces, but urlsplit before Python 3.11.4 did not. So Python and the browser could read a different scheme from the same URL (CVE-2023-24329, gh-102153). The encoding models urlsplit's scheme parsing from the CPython sources and the browser's parsing from the standard, and asks if they can disagree on javascript:.

1

CPython 3.11.2

python · Lib/urllib/parse.py
for b in _UNSAFE_URL_BYTES_TO_REMOVE:     # "\t", "\r", "\n"
    url = url.replace(b, "")
i = url.find(':')
if i > 0 and url[0].isascii() and url[0].isalpha():
    for c in url[:i]:
        if c not in scheme_chars:
            break
    else:
        scheme, url = url[:i].lower(), url[i+1:]
Z3-Noodler · 1.94 s
sat · bug found
url = "\u{0}JAVASCRIPT:alert(1)"

A single NUL byte in front of the URL is enough. urlsplit sees no scheme, so the blocklist passes the URL, and the browser strips the NUL and runs javascript:. Upper case is no obstacle either: the solver mixes it in because both sides compare case-insensitively.

SMT-LIB encoding cases/cpython-3.11.2.smt2 
; CPython 3.11.2, urllib.parse.urlsplit (CVE-2023-24329).  An app blocks
; dangerous link schemes:
;
;   def is_safe_link(url):
;       return urlsplit(url).scheme not in {"javascript", "data", "vbscript"}
;
; urlsplit:
;   for b in _UNSAFE_URL_BYTES_TO_REMOVE:          # "\t", "\r", "\n"
;       url = url.replace(b, "")
;   i = url.find(':')
;   if i > 0 and url[0].isascii() and url[0].isalpha():
;       for c in url[:i]:
;           if c not in scheme_chars: break
;       else:
;           scheme, url = url[:i].lower(), url[i+1:]
(set-logic QF_SLIA)
(declare-const url String)
(define-fun remove_tabs ((s String)) String           ; drop \t, \r, \n
  (str.replace_all (str.replace_all (str.replace_all s "\u{9}" "") "\u{d}" "") "\u{a}" ""))
(define-fun scheme_of ((u String)) String               ; the scheme part of urlsplit
  (let ((s (str.substr u 0 (str.indexof u ":" 0))))
    (ite (and (str.contains u ":")
              (str.in_re s (re.++ (re.union (re.range "a" "z") (re.range "A" "Z"))
                                  (re.* (re.union (re.range "a" "z") (re.range "A" "Z") (re.range "0" "9")
                                                  (str.to_re "+") (str.to_re "-") (str.to_re "."))))))
         (str.to_lower s)
         "")))
(define-fun c0_or_space () RegLan (re.range "\u{0}" " "))
; lstrip(C0 control or space): url = lead ++ rest, rest does not start with one
(declare-const lead String)
(declare-const rest String)
(assert (= url (str.++ lead rest)))
(assert (str.in_re lead (re.* c0_or_space)))
(assert (not (str.in_re rest (re.++ c0_or_space re.all))))
; The browser (WHATWG URL standard) strips leading C0 controls and spaces,
; removes tabs and newlines, and reads the scheme case-insensitively.
; Does it run a javascript: URL that the blocklist let through?
(assert (str.prefixof "javascript:" (str.to_lower (remove_tabs rest))))
(assert (str.suffixof "alert(1)" url))
(define-fun scheme () String (scheme_of (remove_tabs url)))
(assert (not (= scheme "javascript")))
(assert (not (= scheme "data")))
(assert (not (= scheme "vbscript")))
(check-sat)
(get-model)

CVE-2021-29921

CPython: SSRF through octal octets in ipaddress

An SSRF guard checks ipaddress.ip_address(host).is_private before the server connects to a host. Python reads every octet as decimal, but the C library that opens the connection (inet_aton, behind getaddrinfo) reads an octet with a leading 0 as octal, so 010 is 10 for Python and 8 for C (CVE-2021-29921, bpo-36384). Both readings are written with Z3-Noodler's str.to_int, with the octal value computed from the individual digits.

1

CPython 3.9.4

python · Lib/ipaddress.py
if not (octet_str.isascii() and octet_str.isdigit()):
    raise ValueError(msg % octet_str)
if len(octet_str) > 3:
    raise ValueError(msg % octet_str)
octet_int = int(octet_str, 10)
if octet_int > 255:
    raise ValueError("Octet %d (> 255) not permitted" % octet_int)
Z3-Noodler · 0.47 s
sat · bug found
host = "012.00.070.100"

Python 3.9.4 sees the public address 12.0.70.100, but the C library connects to 10.0.56.100 in a private network. We checked the C side with socket.inet_aton, which returns exactly that. Python's three-character limit rules out the well-known 0177.0.0.1, but the solver needs no such trick: it finds the private range that the limit still allows.

SMT-LIB encoding cases/ipaddress-3.9.4.smt2 
; CPython 3.9.4, ipaddress (CVE-2021-29921).  An SSRF guard:
;
;   def is_allowed(host):
;       return not ipaddress.ip_address(host).is_private
;   ...
;   if is_allowed(host): urllib.request.urlopen(f"http://{host}/")
;
; ipaddress reads every octet as decimal, but the C library that opens the
; connection (inet_aton) reads an octet with a leading 0 as octal.
(set-logic QF_SLIA)
(declare-const o1 String) (declare-const o2 String) (declare-const o3 String) (declare-const o4 String)
(declare-const host String)
(assert (= host (str.++ o1 "." o2 "." o3 "." o4)))

; ipaddress._parse_octet: 1-3 ASCII digits, value at most 255
(define-fun py_octet_ok ((o String)) Bool
  (and (str.in_re o ((_ re.loop 1 3) (re.range "0" "9"))) (<= (str.to_int o) 255)))

; inet_aton (glibc, used by getaddrinfo): a leading 0 means octal
(define-fun digit ((o String) (i Int)) Int (str.to_int (str.at o i)))
(define-fun aton_octet ((o String)) Int
  (ite (and (str.prefixof "0" o) (> (str.len o) 1))
       (ite (= (str.len o) 2) (digit o 1) (+ (* 8 (digit o 1)) (digit o 2)))
       (str.to_int o)))
(define-fun aton_ok ((o String)) Bool
  (or (not (str.prefixof "0" o)) (str.in_re o (re.+ (re.range "0" "7")))))

; RFC 1918 private and loopback ranges
(define-fun private ((a Int) (b Int)) Bool
  (or (= a 10) (= a 127) (and (= a 172) (<= 16 b 31)) (and (= a 192) (= b 168))))

(assert (and (py_octet_ok o1) (py_octet_ok o2) (py_octet_ok o3) (py_octet_ok o4)))
(assert (and (aton_ok o1) (aton_ok o2) (aton_ok o3) (aton_ok o4)))
; Python thinks the address is public, the C library connects to a private one.
(assert (not (private (str.to_int o1) (str.to_int o2))))
(assert (private (aton_octet o1) (aton_octet o2)))

CWE-22

Path traversal through a one-pass filter

A file-download endpoint deletes ../ from the requested name so that it cannot leave the upload directory. Filters like this appear in real path traversal advisories again and again. Deleting a pattern can create a new copy of it from the characters on both sides.

1

The original filter

python
def safe_open(name):
    name = name.replace("../", "")
    return open(os.path.join(UPLOAD_DIR, name))
Z3-Noodler · 0.03 s
sat · bug found
name = "....//."

The solver answers with ....//.: removing the ../ in the middle glues the outer .. and / into a new ../.

SMT-LIB encoding cases/path-traversal.smt2 
; Path traversal: a filter that deletes "../" from a user-supplied file name.

;       return open(os.path.join(UPLOAD_DIR, name))
;
; Can the cleaned name still climb out of UPLOAD_DIR?
(set-logic QF_SLIA)
(declare-const name String)                                 ; attacker-controlled
(define-fun cleaned () String (str.replace_all name "../" ""))

CWE-79

Cross-site scripting through tag stripping

A comment form deletes <script> tags before it shows comments to other users. The browser reads tag names case-insensitively, so the encoding checks the lower-cased output with Z3-Noodler's str.to_lower.

1

The original sanitizer

javascript
function sanitize(comment) {
  return comment.replaceAll("<script>", "");
}
Z3-Noodler · 0.14 s
sat · bug found
comment = "<<script>SCRIPT><<script>"

The attack combines two bugs: the filter is case-sensitive and does only one pass. Deleting both <script> tags leaves <SCRIPT><.

A query is built by escaping quotes in user input. The encoding asks if the escaped text can fail to be a well-formed body of a MySQL-style string literal, ([^'\\]|\\.)*. If it does, a quote closes the literal early and the rest of the input runs as SQL.

1

The original escaping

php

The classic: the input \' becomes \\', an escaped backslash followed by a bare quote. We also required the payload to end with OR 1=1 -- , and the solver built a complete exploit around it.

SMT-LIB encoding cases/sql-escape.smt2 
; SQL injection: hand-made escaping of a quoted string literal (MySQL-style
; literals, where "\" escapes the next character).

;   $sql = "SELECT * FROM users WHERE name = '"
;        . str_replace("'", "\\'", $name) . "'";

; out of the literal and append SQL of their choice?

(assert (str.suffixof " OR 1=1 -- " name))
(check-sat)

Why a string solver?

Fuzzers and test suites try inputs one at a time, but the inputs above are rare, such as ....//. or a tab between two slashes. A solver reasons about all strings at once. Its exploits are short and easy to read, and its unsat answers are proofs for every input. Z3-Noodler represents the possible values of each string variable by an automaton. This is why replace_all, regex membership, case conversion and lengths can all appear in the same query. The same technique is used in symbolic execution, in analysis of cloud access policies and in test generation.

Want to try it on your own code? Download a release, open the playground or read the documentation. All queries are in cases/.
