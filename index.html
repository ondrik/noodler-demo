Z3-Noodler · string constraint solving

Finding bugs in string-handling code
with an SMT solver

Sanitizers, URL checks and escaping functions are short, and they still have bugs. Each one rewrites a string and then checks it. We translate the code to string constraints and ask Z3-Noodler if an attacker's input exists. A sat answer comes with a concrete exploit. An unsat answer is a proof that no input works.

9exploits found

≤ 0.25 sper query

How it works

  1. Model the code. Every string operation has a counterpart in the SMT-LIB theory of strings: replace → str.replace_all, startswith → str.prefixof, a regex test → str.in_re. Z3-Noodler also accepts ECMAScript regexes as they are (re.from_ecma2020) and has str.to_lower.
  2. State the attack. Add the attacker's goal: the cleaned path contains ../, the browser sees //host, the SQL literal is not closed properly.
  3. Ask the solver. sat: the model is an input that triggers the bug. unsat: no input does, for strings of any length.

The results below come from a native build of the solver. Run in the playground opens a query in the Z3-Noodler playground, which runs the solver locally via WebAssembly, so you can change the code and try your own fix.

CWE-22

Path traversal through a one-pass filter

A file-download endpoint deletes ../ from the requested name so that it cannot leave the upload directory. Filters like this appear in real path traversal advisories again and again. Deleting a pattern can create a new copy of it from the characters on both sides.

1

The original filter

python
def safe_open(name):
    name = name.replace("../", "")
    return open(os.path.join(UPLOAD_DIR, name))
Z3-Noodler · 0.02 s
sat · bug found
name = "....//."

The solver answers with ....//.: removing the ../ in the middle glues the outer .. and / into a new ../.

SMT-LIB encoding cases/path-traversal.smt2 
; Path traversal: a filter that deletes "../" from a user-supplied file name.
;
;   def safe_open(name):
;       name = name.replace("../", "")
;       return open(os.path.join(UPLOAD_DIR, name))
;
; Can the cleaned name still climb out of UPLOAD_DIR?
(set-logic QF_SLIA)
(declare-const name String)                                 ; attacker-controlled
(define-fun cleaned () String (str.replace_all name "../" ""))
(assert (str.contains cleaned "../"))
(check-sat)
(get-model)

A sound filter

python
name = name.replace("..", "")
Z3-Noodler · 0.02 s
unsat · proved safe

Deleting every .. turns a run of n dots into n mod 2 dots, so no .. survives. Z3-Noodler proves this for all inputs, not just the ones a test suite happens to try.

SMT-LIB encoding cases/path-traversal-fixed.smt2 
; A sound filter: delete every ".." (not just "../").
;
;   name = name.replace("..", "")
;
; A run of n dots becomes n mod 2 dots, so no ".." can be glued together.
; Can the cleaned name still contain ".."?  (unsat = the filter is sound)
(set-logic QF_SLIA)
(declare-const name String)
(assert (str.contains (str.replace_all name ".." "") ".."))
(check-sat)

CWE-79

Cross-site scripting through tag stripping

A comment form deletes <script> tags before it shows comments to other users. The browser reads tag names case-insensitively, so the encoding checks the lower-cased output with Z3-Noodler's str.to_lower.

1

The original sanitizer

javascript
function sanitize(comment) {
  return comment.replaceAll("<script>", "");
}
Z3-Noodler · 0.14 s
sat · bug found
comment = "<<script>SCRIPT><<script>"

The attack combines two bugs: the filter is case-sensitive and does only one pass. Deleting both <script> tags leaves <SCRIPT><.

SMT-LIB encoding cases/xss-strip.smt2 
; XSS: a "sanitizer" that deletes <script> tags from a comment before it is
; put into an HTML page.
;
;   function sanitize(comment) {
;     return comment.replaceAll("<script>", "");
;   }
;
; HTML tag names are case-insensitive, so the browser runs a script if the
; lower-cased output contains "<script>".  Can that happen?
(set-logic QF_SLIA)
(declare-const comment String)
(define-fun out () String (str.replace_all comment "<script>" ""))
(assert (str.contains (str.to_lower out) "<script>"))
(check-sat)
(get-model)

This closes the case hole but not the nesting one. The solver now needs the lower-casing and the replacement together, and still finds an attack.

CWE-601

Open redirect after login

After login, the app redirects to ?next=<url>. To keep users on the site, it accepts local paths but rejects protocol-relative URLs (//evil.example). The encoding models how a browser parses the URL under the WHATWG URL standard: it removes tabs and newlines and treats \ like /.

1

The original check

python
def is_safe_redirect(url):
    return url.startswith("/") and not url.startswith("//")
Z3-Noodler · 0.03 s
sat · bug found
url = "/\u{9}/"

/\t/ (slash, tab, slash) passes the check. The browser deletes the tab and goes to another host.

SMT-LIB encoding cases/open-redirect.smt2 
; Open redirect: after login, the app redirects to ?next=<url>.  To stay on
; the same site, it accepts paths but not protocol-relative URLs (//host).
;
;   def is_safe_redirect(url):
;       return url.startswith("/") and not url.startswith("//")
;
; What the browser makes of the URL (WHATWG URL standard): it removes tabs
; and newlines, and treats "\" like "/".  Can it start with "//", i.e. go to
; another host?
(set-logic QF_SLIA)
(declare-const url String)
(define-fun browser ((s String)) String
  (str.replace_all
    (str.replace_all (str.replace_all (str.replace_all s "\u{9}" "") "\u{a}" "") "\u{d}" "")
    "\u{5c}" "/"))
(assert (str.prefixof "/" url))
(assert (not (str.prefixof "//" url)))
(assert (str.prefixof "//" (browser url)))
(check-sat)
(get-model)

The quick fix: normalize backslashes

python
def is_safe_redirect(url):
    u = url.replace("\\", "/")
    return u.startswith("/") and not u.startswith("//")
Z3-Noodler · 0.03 s
sat · bug found
url = "/\u{9}//"

The patch fixes the backslash bypass from a bug report but not the tab bypass, and the solver finds it right away. A deny-list has to model the parser exactly, so it is easy to get wrong.

SMT-LIB encoding cases/open-redirect-backslash.smt2 
; A "fix" after the first bug report: also check with backslashes turned
; into slashes.
;
;   def is_safe_redirect(url):
;       u = url.replace("\\", "/")
;       return u.startswith("/") and not u.startswith("//")
;
; Is that enough?
(set-logic QF_SLIA)
(declare-const url String)
(define-fun browser ((s String)) String
  (str.replace_all
    (str.replace_all (str.replace_all (str.replace_all s "\u{9}" "") "\u{a}" "") "\u{d}" "")
    "\u{5c}" "/"))
(define-fun u () String (str.replace_all url "\u{5c}" "/"))
(assert (str.prefixof "/" u))
(assert (not (str.prefixof "//" u)))
(assert (str.prefixof "//" (browser url)))
(check-sat)
(get-model)

The fix: an allow-list

python
SAFE = re.compile(r"/(?:[A-Za-z0-9._~-][A-Za-z0-9._~/-]*)?(?:\?[A-Za-z0-9=&._~-]*)?")

def is_safe_redirect(url):
    return SAFE.fullmatch(url) is not None
Z3-Noodler · 0.03 s
unsat · proved safe

The regular expression is pasted into the query as is, through Z3-Noodler's re.from_ecma2020. Unsat: none of the accepted URLs leaves the site, with any combination of the browser's rewrites.

SMT-LIB encoding cases/open-redirect-fixed.smt2 
; The fix: an allow-list of characters instead of a deny-list of prefixes.
;
;   SAFE = re.compile(r"/(?:[A-Za-z0-9._~-][A-Za-z0-9._~/-]*)?(?:\?[A-Za-z0-9=&._~-]*)?")
;   def is_safe_redirect(url):
;       return SAFE.fullmatch(url) is not None
;
; Can an accepted url go to another host?  (unsat = no)
(set-logic QF_SLIA)
(declare-const url String)
(define-fun browser ((s String)) String
  (str.replace_all
    (str.replace_all (str.replace_all (str.replace_all s "\u{9}" "") "\u{a}" "") "\u{d}" "")
    "\u{5c}" "/"))
(assert (str.in_re url (re.from_ecma2020 '/(?:[A-Za-z0-9._~-][A-Za-z0-9._~/-]*)?(?:\?[A-Za-z0-9=&._~-]*)?')))
(assert (str.prefixof "//" (browser url)))
(check-sat)

CWE-918

Server-side request forgery through an unescaped dot

A webhook may only call the company's own API servers, and a regular expression checks the URL before the server fetches it. The encoding states the attacker's goal: a URL that passes the check, whose host is not a subdomain of example.com, and that ends in .com, so anyone can register it.

1

The original check

javascript
const ALLOWED = /^https:\/\/(www|api).example.com\//;
if (!ALLOWED.test(url)) throw new Error("forbidden host");
await fetch(url);
Z3-Noodler · 0.03 s
sat · bug found
host = "api-example.com"
url = "https://api-example.com/"
path = ""

In a regular expression, . matches any character, so the attacker can register api-example.com and the check lets it through.

SMT-LIB encoding cases/url-allowlist.smt2 
; URL allow-list: a webhook may only call our own API servers.
;
;   const ALLOWED = /^https:\/\/(www|api).example.com\//;
;   if (!ALLOWED.test(url)) throw new Error("forbidden host");
;   fetch(url);
;
; Is there an allowed url whose host is NOT example.com or one of its
; subdomains?
(set-logic QF_SLIA)
(declare-const url String)
(declare-const host String)
(declare-const path String)
(assert (str.in_re url (re.from_ecma2020 '^https://(www|api).example.com/.*')))
(assert (= url (str.++ "https://" host "/" path)))
(assert (str.in_re host (re.+ (re.union (re.range "a" "z") (re.range "0" "9") (str.to_re "-") (str.to_re ".")))))
(assert (str.suffixof ".com" host))                          ; registrable by the attacker
(assert (not (str.in_re host (re.from_ecma2020 '([a-z0-9-]+\.)*example\.com'))))
(check-sat)
(get-model)

CWE-89

SQL injection through hand-made escaping

A query is built by escaping quotes in user input. The encoding asks if the escaped text can fail to be a well-formed body of a MySQL-style string literal, ([^'\\]|\\.)*. If it does, a quote closes the literal early and the rest of the input runs as SQL.

1

The original escaping

php
$sql = "SELECT * FROM users WHERE name = '"
     . str_replace("'", "\\'", $name) . "'";
Z3-Noodler · 0.03 s
sat · bug found
name = "\' OR 1=1 -- "

The classic: the input \' becomes \\', an escaped backslash followed by a bare quote. We also required the payload to end with OR 1=1 -- , and the solver built a complete exploit around it.

SMT-LIB encoding cases/sql-escape.smt2 
; SQL injection: hand-made escaping of a quoted string literal (MySQL-style
; literals, where "\" escapes the next character).
;
;   $sql = "SELECT * FROM users WHERE name = '"
;        . str_replace("'", "\\'", $name) . "'";
;
; The literal stays closed iff the escaped text is a sequence of ordinary
; characters and backslash escapes: ([^'\\]|\\.)*.  Can the attacker break
; out of the literal and append SQL of their choice?
(set-logic QF_SLIA)
(declare-const name String)
(define-fun escaped () String (str.replace_all name "'" "\u{5c}'"))
(assert (not (str.in_re escaped (re.from_ecma2020 '([^\x27\\]|\\.)*'))))
(assert (str.suffixof " OR 1=1 -- " name))
(check-sat)
(get-model)
Run in the playground ↗
2

The fix: escape the escape character first

php
$esc = str_replace("'", "\\'", str_replace("\\", "\\\\", $name));
Z3-Noodler · 0.02 s
unsat · proved safe

Unsat: two chained replace_alls, which Z3-Noodler handles as a composition of transducers, never produce a broken literal. (Prepared statements are still the better fix.)

SMT-LIB encoding cases/sql-escape-fixed.smt2 
; The fix: escape the escape character first (or, better, use a prepared
; statement).
;
;   $esc = str_replace("'", "\\'", str_replace("\\", "\\\\", $name));
;
; Can the attacker still break out of the literal?  (unsat = no)
(set-logic QF_SLIA)
(declare-const name String)
(define-fun escaped () String
  (str.replace_all (str.replace_all name "\u{5c}" "\u{5c}\u{5c}") "'" "\u{5c}'"))
(assert (not (str.in_re escaped (re.from_ecma2020 '([^\x27\\]|\\.)*'))))
(check-sat)

3

Then someone truncates the value

php
$esc = str_replace("'", "\\'", str_replace("\\", "\\\\", $name));
$esc = substr($esc, 0, 16);   // fit the column
Z3-Noodler · 0.04 s
sat · bug found
name = "'''''''a'a"

Cutting the value after escaping can split an escape sequence in two. The solver finds an input of only letters and quotes whose escaped form is cut right after a backslash, and that backslash escapes the closing quote. This needs string lengths, positions and the transducers together.

SMT-LIB encoding cases/sql-truncate.smt2 
; Escaping is now correct, but the escaped value is cut to fit a 16-character
; column (or a log line, or a cache key) *after* escaping:
;
;   $esc = str_replace("'", "\\'", str_replace("\\", "\\\\", $name));
;   $esc = substr($esc, 0, 16);
;
; Can the cut leave an unfinished escape that eats the closing quote?
(set-logic QF_SLIA)
(declare-const name String)
(define-fun escaped () String
  (str.replace_all (str.replace_all name "\u{5c}" "\u{5c}\u{5c}") "'" "\u{5c}'"))
(define-fun cut () String (str.substr escaped 0 16))
(assert (not (str.in_re cut (re.from_ecma2020 '([^\x27\\]|\\.)*'))))
(assert (str.in_re name (re.* (re.union (re.range "a" "z") (str.to_re "'")))))  ; only letters and quotes
(check-sat)
(get-model)

Why a string solver?

Fuzzers and test suites try inputs one at a time, but the inputs above are rare, such as ....//. or a tab between two slashes. A solver reasons about all strings at once. Its exploits are short and easy to read, and its unsat answers are proofs for every input. Z3-Noodler represents the possible values of each string variable by an automaton. This is why replace_all, regex membership, case conversion and lengths can all appear in the same query. The same technique is used in symbolic execution, in analysis of cloud access policies and in test generation.
